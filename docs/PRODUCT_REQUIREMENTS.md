## 1. 文档目的

本文定义一套基于 Windows UI Automation（以下简称 UIA）的微信机器人产品功能范围、管理能力、可靠性要求和验收基线，作为后续原型、架构设计、开发排期和测试验收的依据。

本产品定位为企业自有微信账号的合规自动化工具，不提供绕过微信登录、安全验证、验证码、风控、封禁、客户端限制或非官方多开的能力，也不将 UIA 能力描述为微信官方接口。

## 2. 产品目标

1. 通过 UIA 在受控 Windows 桌面会话中稳定识别微信窗口、读取新消息并执行回复。
2. 支持多个机器人执行端和多个已授权微信账号的集中管理。
3. 支持规则回复、业务接口、人工客服、定时任务和受控批量触达。
4. 提供可审计、可监控、可暂停、可恢复的商业级运行体系。
5. 提供租户级和系统级备份、恢复、回滚及灾难恢复演练能力。

## 3. 产品组成

| 组成 | 主要职责 |
| --- | --- |
| Windows 自动化执行端（Agent） | 检测微信、捕获消息、执行 UI 操作、状态确认、截图留证、异常自愈 |
| 机器人业务服务 | 消息标准化、规则匹配、会话锁、任务队列、幂等、重试、业务集成 |
| 后台管理平台 | 账号设备、会话客服、规则任务、组织权限、审计报表、运维管理 |
| 数据与灾备系统 | 数据库、附件、日志、备份清单、校验、恢复和演练 |

## 4. 关键边界与约束

### 4.1 技术边界

- UIA 依赖微信版本、Windows 版本、界面语言、主题、DPI、分辨率和窗口结构。
- 执行端必须运行在已登录且未锁定的交互式 Windows 桌面中；锁屏、休眠、RDP 会话断开可能使自动化失败。
- 每个生产机器人使用独立受控 Windows 会话或独立主机，避免焦点和剪贴板争抢。
- UI 操作必须串行化；同一个微信实例不得并发点击多个会话。
- UIA 不适合超高并发、严格实时或依赖可靠送达回执的业务；正式客服和通知场景应先评估企业微信、微信开放平台等官方能力。
- 未识别的微信版本、关键控件缺失或目标会话身份不确定时必须安全暂停，禁止猜测点击。
- 系统不承诺读取微信客户端未展示、已撤回或执行端离线期间遗漏的完整历史消息。
- 发送结果分为“UI 操作完成”“客户端界面已显示”和“对方已送达”；UIA 通常只能可靠确认前两级。
- 微信登录态、密码和官方客户端内部数据库不作为可移植备份对象；灾后可能需要授权人员重新扫码登录。

### 4.2 业务与合规边界

- 仅管理客户已授权的账号、联系人和业务场景。
- 默认禁用无授权营销、批量加好友、批量拉群和绕过退订等高风险能力。
- 批量外发必须支持审批、频控、黑名单、退订、静默时段和完整审计。
- 付款、转账、合同承诺、医疗或金融建议、身份验证及敏感信息外发必须转人工确认。
- 不保存微信密码，不自动绕过二维码、验证码、安全验证或账号风控。
- 聊天正文、附件、截图和诊断录像按敏感数据管理，遵循最小采集、最短保留和最小授权原则。
- 正式商用前需由客户法务评估微信平台规则、个人信息保护、数据跨境和行业监管要求。

## 5. 用户与角色

| 角色 | 主要职责 |
| --- | --- |
| 平台超级管理员 | 租户、套餐、全局配置和平台运维；默认无权查看租户聊天正文 |
| 平台运维员 | 设备、执行端、版本、健康状态和故障诊断 |
| 安全审计员 | 只读查看登录、授权、敏感操作、备份与恢复审计 |
| 租户所有者 | 本租户组织、账单、管理员和数据策略 |
| 租户管理员 | 用户、角色、账号、设备、规则、任务和集成 |
| 运营主管 | 审批规则及批量任务、查看报表、管理客服队列 |
| 规则编辑员 | 创建、测试规则；无权独立发布高风险规则 |
| 任务操作员 | 创建、预约、暂停任务；批量任务按策略审批 |
| 客服主管 | 技能组、分配策略、SLA、质检和强制转派 |
| 客服人员 | 处理被分配的会话、回复、备注和结束接管 |
| 设备维护员 | 设备注册、自检、扫码协助和维护模式；默认无权查看业务内容 |
| 观察员 | 只读查看授权范围内的数据和报表 |

权限需同时约束功能、租户、部门、微信账号、客服组、数据范围、操作类型和敏感字段，不得仅依靠前端隐藏按钮。

## 6. 功能优先级定义

| 级别 | 含义 |
| --- | --- |
| P0 | 商业可用首版必须具备，缺失时不可上线 |
| P1 | 首版后优先补齐，明显提升业务完整性或运维效率 |
| P2 | 规模化和高级场景能力 |

## 7. Windows 自动化执行端

### 7.1 环境与登录检测（P0）

- 注册设备并绑定租户、环境、Windows 会话和微信账号。
- 检测 Windows 版本、分辨率、DPI、语言、主题、权限级别、锁屏和休眠状态。
- 检测微信进程、主窗口、客户端版本、登录状态和关键 UIA 控件。
- 提供上线前能力自检和收发测试，生成明确的通过/失败报告。
- 扫码、验证码或风控验证时进入“等待人工处理”，通知授权人员。
- 支持在线、忙碌、人工操作、维护、异常、离线和禁用状态。

### 7.2 消息采集（P0）

- 扫描会话列表和未读标记，识别单聊及群聊新消息。
- 首版支持文本消息；图片、文件、链接、语音等建立统一附件模型并分期启用。
- 记录来源账号、会话、发送方、消息方向、客户端显示时间和本地捕获时间。
- 为每条事件生成唯一标识，并通过内容指纹、窗口和时间窗去重。
- 保证单会话内顺序处理；无法确定顺序时标记为“顺序不确定”。
- 对不支持的消息类型保留占位事件，禁止误判成普通文本。

### 7.3 UI 操作执行（P0）

- 支持定位会话、打开聊天、输入文本、发送并检查聊天区域结果。
- 执行动作前再次校验目标账号、会话名称和关键界面特征。
- 同一微信实例使用单一动作队列，防止焦点冲突和串话。
- 支持超时、取消、有限重试及不可重试错误分类。
- 发送结果至少记录：待执行、执行中、界面已确认、结果不确定、失败、已取消。
- “已点击但未确认”的任务不得直接自动重发，需进入待核对状态。
- 关键操作保存前后截图；截图按敏感数据策略脱敏、授权和过期清理。

### 7.4 异常恢复（P0）

- 检测窗口丢失、失焦、遮挡、弹窗、网络异常、微信崩溃和执行线程卡死。
- 微信崩溃时可受控拉起；登录失效或未知弹窗时停止外发并告警。
- UI 结构和兼容基线不一致时进入安全模式，不继续发送。
- 支持 Agent 心跳、看门狗、维护模式、受控重启和紧急停止。
- 中控失联时按策略限时运行，商用默认在超时后暂停领取新任务。
- 采集结构化日志、指标、UIA 控件树摘要和脱敏诊断包。

### 7.5 版本兼容（P0）

- 建立微信版本、Windows 版本、DPI、语言和主题的兼容矩阵。
- 新微信版本先在测试池验证，再灰度到少量生产实例。
- UI 适配包需版本化、签名、灰度发布和一键回滚。
- 支持禁止微信自动升级或在检测到升级后自动进入维护状态。

## 8. 机器人业务核心

### 8.1 消息管道（P0）

- 采集事件标准化、去重、排序、持久化和状态跟踪。
- 使用全局事件 ID、任务 ID、动作 ID 和 Trace ID 串联全链路。
- 会话级互斥锁防止机器人、后台客服和批量任务同时回复。
- 支持动作优先级、超时、取消、重试、死信和人工处理。
- 幂等键覆盖事件消费、规则执行、业务接口调用和 UI 外发。
- 保留原始事件摘要及解析结果，支持问题复盘。

### 8.2 规则引擎（P0）

- 触发器：收到消息、关键词、群内 @、时间、任务结果、人工状态变化。
- 条件：账号、联系人、群、标签、消息类型、时间段和组合表达式。
- 动作：自动回复、调用业务 API、打标签、创建工单、通知和转人工。
- 支持规则优先级、命中后停止/继续、冷却时间、防循环和防重复触发。
- 每个规则动作执行前校验目标联系人或群的有效服务权益，无权益时进入未激活提示或转人工流程。
- 支持模板变量、默认值、长度检查和发送前预览。
- 规则采用草稿、模拟、审核、发布、暂停、回滚和归档生命周期。
- 生产发布生成不可变版本，记录修改差异、发布人、审批人和适用范围。
- 规则模拟器显示样例消息的匹配路径、变量和最终动作。
- 接口超时、失败、空结果或内容审核失败时支持兜底分支。

### 8.3 AI 与知识库（P1）

- 可接入可替换的大模型及企业知识库，不与 UIA 执行层耦合。
- 支持提示词版本、知识范围、引用来源、会话记忆长度和费用上限。
- 支持敏感问题拒答、置信度阈值、事实校验和低置信度转人工。
- 模型调用前后执行个人信息脱敏和内容安全检查。
- 记录模型、版本、耗时、Token、命中知识和输出审核结果。

### 8.4 业务集成（P1）

- 提供带鉴权、限流、签名和幂等的 REST API 与 Webhook。
- 支持 CRM、工单、订单、会员、库存等业务服务查询。
- 支持请求/响应字段映射、超时、重试、熔断和降级。
- API 密钥按租户隔离，支持有效期、轮换、撤销和使用审计。

## 9. 消息与会话中心

### 9.1 会话工作台（P0）

- 提供收件箱、机器人处理中、待人工、人工处理中、已解决和异常视图。
- 按账号、联系人、群、标签、负责人、状态和时间检索。
- 展示消息方向、类型、捕获时间、发送状态和关联任务。
- 支持文本回复、快捷回复、模板回复、内部备注和会话标签。
- 支持负责人分配、转派、关注、关闭和重新打开。
- 提示未回复、SLA 超时、发送失败和机器人异常。
- 展示规则命中、业务接口、UI 动作和截图等审计轨迹。
- 会话导出需权限、审批、水印、脱敏和审计。

### 9.2 人工接管（P0）

- 支持用户请求人工、关键词、负面情绪、连续未命中、VIP 和异常自动转人工。
- 支持技能组分配、指定客服、排队和抢单。
- 接管时原子锁定会话，机器人和批量任务停止对该会话发送。
- 客服可查看授权范围内的上下文、客户资料和规则命中记录。
- 无客服在线时发送排队提示或执行配置的兜底方案。
- 结束接管时记录处理结果、标签和摘要，经过冷却期后恢复机器人。
- 强制接管、强制释放和越级转派需专门权限并写审计。
- 检测后台客服和微信客户端人工输入的潜在冲突。

## 10. 联系人与群管理

### 10.1 联系人（P0）

- 同步 UI 可见的昵称、备注、微信号可见值、头像和来源账号。
- 支持标签、客户分组、自定义字段、负责人和最近互动时间。
- 支持根据客户编号、业务名称、套餐和到期日等字段生成联系人备注。
- 备注规则使用模板，例如 `{客户编号}-{业务名称}-{到期日}`，支持预览、长度校验、空值处理和非法字符处理。
- 系统内备注是主数据；仅在目标身份可再次确认且当前微信版本支持时，才通过 UIA 同步微信联系人备注。
- 支持手工备注保护、冲突检测、覆盖/跳过策略、批量限速、失败重试和单条回滚。
- 每次备注生成、人工修改、微信同步及回滚均记录旧值、新值、规则版本、操作者和结果。
- 支持白名单、黑名单、免打扰、禁止自动回复和退订状态。
- 提供重复联系人合并建议，但不在身份不确定时自动合并。
- UI 无法再次确认的资料标记为“可能过期”，不得视为官方实时数据。
- CSV/Excel 导入导出支持校验、预览、错误报告和重复处理策略。

### 10.2 群聊（P0）

- 同步群基本资料、群成员可见快照、来源账号和群标签。
- 支持系统内群备注、业务名称、服务套餐、负责人和服务到期日。
- 支持群备注模板、批量生成、冲突保护、变更预览、审计和回滚。
- 微信客户端支持群备注编辑时可受控同步；不支持时仅维护系统内备注，不通过改群名冒充备注功能。
- 监听群内新消息并区分 @机器人、@所有人、@其他成员、多重 @ 和普通文本。
- @机器人消息进入高优先级队列，可按群、成员角色、关键词、通用功能包和权益路由到不同服务。
- 支持群关键词、@机器人、入群欢迎、问题转人工和群级静默时段。
- 防止机器人响应自己发送的消息；同一消息只触发一次，并支持冷却时间、连续调用上限和异常熔断。
- UIA 无法稳定获得 @ 的语义或发送者身份时标记为待确认，不根据显示昵称猜测授权身份。
- 支持群级频控、禁止自动回复和敏感群保护。
- 群管理员类操作单独授权、二次确认和审计。

### 10.3 群内 @ 消息处理流程（P0）

群消息捕获 -> @ 语义识别 -> 消息去重 -> 群和成员身份映射 -> 服务权益校验 -> 通用功能包路由 -> 频控与内容检查 -> 自动回复或转人工 -> 结果审计。

- 未激活服务时返回可配置的服务说明或激活引导，不执行付费能力。
- 已过期、已冻结或已撤销时返回对应状态消息，禁止继续调用高级功能。
- @ 消息包含激活命令时，只创建激活请求；必须继续验证激活码、订单或授权管理员身份。
- 涉及付费、账号安全、敏感数据或其他高风险功能时转人工确认。

## 11. 任务中心

### 11.1 任务编排（P0）

- 支持单次、定时和周期任务。
- 目标可选择联系人、标签人群、群聊或指定会话。
- 支持模板变量、样例数据预览、测试账号试发和发送前校验。
- 生命周期：草稿、待审批、已预约、执行中、已暂停、部分完成、已完成、失败、已取消。
- 支持账号分片、会话亲和路由、分时段、分批次、随机间隔和每日上限。
- 发送前检查去重、黑名单、退订、静默时段、账号额度和会话锁。
- 支持暂停、继续、取消；取消只影响尚未开始的动作。
- 高风险批量任务支持双人审批和全局紧急停止。

### 11.2 任务结果（P0）

- 按账号、批次和错误类型显示进度、成功率、失败率与待确认数。
- 失败分类至少包括账号离线、会话未找到、UI 失败、内容失败、超时和未知。
- 仅对明确可重试且通过幂等校验的失败项重试。
- 暂停或灾后恢复时只处理确认未执行的动作，不盲目重放。
- 支持导出经过脱敏的执行报告和完整审计记录。

## 12. 多账号、设备与租户

### 12.1 账号与设备（P0）

- 管理微信账号、机器人实例、Windows 主机和 Windows 会话的绑定关系。
- 展示在线状态、微信版本、最后心跳、队列、负载、今日用量和异常次数。
- 配置业务用途、服务时段、每日额度、发送速率和允许的能力。
- 联系人或群保持账号亲和，离线后默认暂停，不盲目迁移到其他账号。
- 仅未执行且满足业务约束和幂等条件的动作允许重新路由。
- 支持启动、暂停、停止接单、维护、受控重启、下线和紧急停止。
- 二维码登录由授权人员确认，扫码及远程诊断全程审计。

### 12.2 多租户（P0 数据模型，P1 产品化）

- 支持租户、部门、团队、岗位、用户和环境隔离。
- 所有业务数据强制绑定租户标识，数据库、缓存、文件、队列、日志和备份均校验租户范围。
- 支持账号数、并发数、存储量、任务量等套餐和配额。
- 支持租户级品牌、时区、语言、保留策略和第三方集成。
- 跨租户运维访问需要临时授权、原因、时限和独立审计。
- 支持租户停用、冻结、数据导出、注销和按策略销毁。

## 13. 后台管理平台

### 13.1 首页与运营看板（P0）

- 展示机器人在线率、微信登录率、UIA 可用率、消息量、发送成功率和待人工数量。
- 展示队列积压、规则错误、异常账号、备份新鲜度和当前告警。
- 支持按租户、账号、设备、版本和时间下钻。
- 指标需标明统计口径，严格区分“界面确认”和“实际送达”。

### 13.2 配置与发布中心（P0）

- 统一管理规则、模板、频控、静默时段、白黑名单和功能开关。
- 支持草稿、差异比较、影响预览、审核、灰度发布和回滚。
- 高风险变更支持双人复核；所有生产配置保留不可变版本。
- 支持配置导入导出、不同环境对比和敏感值加密。

### 13.3 用户、权限与认证（P0）

- 支持 RBAC 并叠加资源范围和敏感字段权限。
- 支持 MFA、密码策略、登录失败锁定、会话超时、强制下线和异地提醒。
- 企业版支持 OIDC、SAML 或 AD 单点登录（P1）。
- 业务配置、运维、审计和备份恢复职责分离。
- 恢复、批量外发、聊天导出、数据删除和敏感查看支持审批。

### 13.4 审计中心（P0）

- 记录操作者、时间、来源 IP、设备会话、租户、账号、对象和结果。
- 配置变更记录修改前后差异、理由、审批人和关联任务。
- 覆盖登录、授权、规则发布、外发、导出、删除、远程诊断、备份和恢复。
- 敏感数据查看行为单独记录。
- 审计日志只追加，普通管理员无权修改或删除；可采用独立审计库、哈希链或不可变存储。
- 默认保留不少于一年，并允许按合同和法规调整。

### 13.5 服务商品与功能包（P0）

- 使用“服务商品 -> 套餐版本 -> 功能包 -> 功能点 -> 权益实例”模型，禁止在机器人规则中写死套餐判断。
- 套餐版本发布后不可直接修改已有客户权益；变更时创建新版本并提供迁移策略。
- 功能点支持启用状态、依赖项、互斥项、调用额度、并发额度、适用对象和配置参数。
- 权益可绑定租户、微信账号、联系人、群聊或业务项目，并明确授权范围。
- 后端 API 和 Agent 均执行权益校验，不能仅在管理页面隐藏功能。
- 首期支持基础服务包、高级通用群服务和定制功能包及其组合销售；游戏专属包延期。
- 支持试用、正式、赠送和补偿权益，并要求来源、原因、审批和审计。

建议初始套餐：

| 套餐 | 建议功能 |
| --- | --- |
| 基础服务 | 自动备注、群内 @ 响应、帮助菜单、基础问答、公告提醒、人工转接、基础报表 |
| 高级群内玩法 | 依赖基础服务包；提供签到、积分、排行、活动报名、组队、抽取非现金虚拟奖励、定时互动、高级统计 |
| 游戏专属服务（延期） | 不纳入当前实现；未来按独立适配包评审 |
| 定制功能 | 客户专属规则、第三方系统集成、专属报表、特定业务适配和定制运维等级 |

群内玩法不得提供现金赌博、变相博彩、违规引流、刷量或绕过游戏平台规则的能力。

### 13.6 服务期限与权益状态（P0）

支持以下标准期限：

| 期限 | 计算规则 |
| --- | --- |
| 30 天 | 从激活时间起增加 30 个自然日 |
| 60 天 | 从激活时间起增加 60 个自然日 |
| 90 天 | 从激活时间起增加 90 个自然日 |
| 半年 | 从激活时间起增加 6 个自然月，同日不存在时取该月最后一日 |
| 一年 | 从激活时间起增加 12 个自然月，同日不存在时取该月最后一日 |
| 永久 | 不设置业务到期时间，但仍可因合同终止、违规、安全事件或管理员审批而冻结或撤销 |

- 所有时间以租户时区展示、UTC 保存，精确记录开始时间和结束时间。
- 有效时间统一使用 `[开始时间, 结束时间)` 半开区间，避免相邻续费权益在边界时刻重复生效。
- 权益状态包括待激活、已预约、有效、宽限期、已暂停、已过期、已撤销和已退款。
- 支持立即生效、预约生效、续费叠加、指定日期续期、升级、降级、转移、冻结和撤销。
- 默认续费从当前结束时间顺延；已过期权益默认从重新激活时间开始，后台可按审批调整。
- 套餐升级需定义剩余时长保留或价值折算策略，计算结果必须在确认前预览。
- 暂停默认不停止期限计时；商务补偿通过新增补偿权益完成，不修改原始购买记录。
- 到期时先阻止新的付费功能调用，正在执行的单个动作安全结束后停止，不强行中断 UI 操作。
- 永久权益仅表示指定功能版本、作用范围和配额没有业务到期日，不默认包含永久托管、免费升级、技术支持或第三方接口费用。
- 永久权益不是不可撤销的技术后门，仍受租户状态、账号状态、产品下线和安全策略约束。

### 13.7 激活、续费与服务消息（P0）

- 激活来源支持后台人工开通、订单支付回调、一次性激活码和授权群管理员命令。
- 群消息中的激活请求不能单独授予权益；必须验证订单、激活码或后台授权。
- 激活码仅保存哈希，支持一次性使用、有效期、套餐绑定、目标范围限制、防暴力尝试及作废。
- 激活码兑换必须事务化、幂等且防重放；同一单次码并发提交只能生成一份有效权益。
- 不使用群昵称、联系人昵称或可重复的显示名称作为唯一激活身份。
- 群内不得回显用户发出的完整激活码；支付、退款和开票通过正式订单系统处理，不使用 UIA 模拟支付。
- 激活前展示目标群/联系人、套餐、期限、生效时间和订单号，并要求确认。
- 支持激活成功、续费成功、升级成功、即将到期、已过期、冻结、撤销和激活失败消息模板。
- 到期提醒默认支持提前 30 天、7 天、3 天、1 天和到期时发送，可按套餐配置且必须防重复。
- 服务消息显示套餐、功能摘要、开始/结束时间和服务单号，不发送完整激活码、密钥或敏感订单信息。
- 所有开通、续费、转移、补偿、冻结、退款和撤销操作写入不可变权益流水。
- 权益判定依次检查全局急停、租户/账号状态、绑定范围、有效时间、套餐依赖、功能授权和配额，后台展示“为什么允许/拒绝”的判定轨迹。
- 有额度的功能执行前原子预占配额，明确失败时按规则返还；UIA 结果不确定时进入人工核对，不自动返还后再次执行。

### 13.8 游戏专属服务与扩展机制（延期，不纳入当前实现）

- 公共能力与游戏专属能力分离，采用版本化游戏适配包注册，不在核心代码中堆叠游戏判断。
- 每个游戏适配包声明游戏标识、支持区服、命令、配置表单、数据源、所需功能点、权限和兼容版本。
- 支持同一群绑定一个或多个游戏，并为不同游戏设置独立命令前缀、角色映射和数据权限。
- 游戏功能可包括角色/区服绑定、官方或授权数据查询、活动日历、战绩/进度、组队报名、签到积分和群排行。
- 第三方游戏数据接口需配置鉴权、限流、缓存、超时、熔断、数据来源展示和降级回复。
- 游戏适配包支持测试、审核、灰度、版本锁定、回滚和停用；停用不得破坏客户历史数据。
- 新游戏上线前完成合法性、数据授权、命令冲突、负载和内容安全评审。
- 不提供外挂、作弊、代控账号、绕过游戏平台风控或赌博性质的游戏能力。

### 13.9 定制功能管理（P1）

- 定制需求使用独立项目记录客户、业务场景、范围、验收标准、版本、交付物和维护期限。
- 生命周期包括需求确认、报价/审批、开发、测试、客户验收、灰度发布、正式启用和维护结束。
- 定制功能仍通过功能点和权益授权启用，不允许为客户创建无法审计的隐藏开关。
- 不允许客户上传并直接执行任意代码；定制模块必须经过代码审查、安全测试、签名发布和资源隔离。
- 明确公共产品升级兼容范围、定制版本升级费用、源代码归属、数据责任和服务等级。
- 支持将成熟定制能力升级为标准功能包，但必须处理客户授权和知识产权边界。

### 13.10 产品化运营（P1）

- 管理许可证、版本、套餐、价格、订单、配额、功能开关和到期提醒。
- 提供权益列表、即将到期、已过期、激活失败和异常使用看板。
- 配置邮件、短信、Webhook 和微信服务消息等通知渠道。
- 提供租户、套餐和功能点维度的使用量、资源成本和计费报表。
- 支持订单、权益和实际功能使用记录对账，发现不一致时告警并禁止静默修正。

## 14. 运维、监控与告警

### 14.1 健康检查（P0）

- 分层检查 Windows 主机、交互桌面、微信进程、登录状态、UIA 探针和关键控件。
- 检查 Agent、中控 API、数据库、缓存、消息队列、对象存储和通知通道。
- 检查 CPU、内存、磁盘、句柄、网络、时间同步、证书、密钥和许可证到期时间。
- 检查最近成功备份、完整性校验和恢复演练结果。

### 14.2 可观测性（P0）

- 指标：在线率、捕获量、成功率、重试率、重复抑制数、队列长度和任务耗时。
- UIA 指标：控件识别失败、窗口失焦、未知弹窗、版本不兼容和自动恢复成功率。
- 使用结构化日志和 Trace ID 串联采集、规则、队列、UI 操作和结果。
- 日志默认脱敏，禁止记录密码、令牌、密钥和无必要的完整聊天正文。
- 支持按任务 ID、机器人、微信账号、时间和错误码检索。

### 14.3 告警与自愈（P0）

- 告警支持等级、聚合、抑制、维护窗口、升级和恢复通知。
- 微信掉线、UI 结构异常、失败率突增、队列积压、磁盘不足和备份过期必须告警。
- 提供全局、租户和单机器人三级紧急停止。
- 自动更新需灰度执行，保留上一稳定版本和回滚能力。
- 提供故障等级、值班规则、升级路径、运行手册和事故复盘记录。

## 15. 数据安全与隐私

- 传输使用 TLS，数据库、对象存储和备份静态加密。
- 密钥由独立 KMS 或等效系统管理，支持轮换和最小授权。
- 密码、Token、API Key 等密钥不得写入日志、截图或明文配置。
- 聊天正文、附件、截图和诊断包分别配置访问权限与保留周期。
- 支持个人信息查询、更正、导出、删除、授权撤回和处理留痕。
- 敏感导出支持审批、脱敏、水印、有效期和下载次数限制。
- 删除按软删除、保留期、最终销毁流程执行，并处理备份中的延迟删除说明。
- 定期执行依赖漏洞扫描、主机加固、权限复核和安全测试。

## 16. 备份与恢复

### 16.1 备份范围（P0）

- 租户、用户、角色、权限和资源范围。
- 机器人、主机、Windows 会话与微信账号映射。
- 规则、模板、流程、版本、频控和系统配置。
- 服务商品、套餐版本、通用功能点、订单、权益、激活码哈希和不可变权益流水；延期的游戏适配包不属于当前备份验收范围。
- 联系人、群、会话、业务记录和合法授权保存的附件。
- 任务、幂等键、执行检查点、死信和待确认动作。
- 审计日志、发布元数据、UI 适配包及兼容矩阵。
- 微信密码、不可移植登录态和官方客户端内部数据库不纳入可恢复承诺。

### 16.2 备份策略（P0）

- 数据库支持全量、增量及时间点恢复；数据库与文件使用一致性清单。
- 遵循 3-2-1 原则：至少三份、两种介质、一份异地。
- 至少一份采用不可变或离线存储，防止勒索软件及管理员误删。
- 传输和落盘加密，备份密钥与备份数据分离存放。
- 每份备份生成清单、版本、时间范围、文件哈希和自动校验结果。
- 保留策略按每日、每周、每月分层配置，支持租户和数据类型差异。
- 备份失败、超过 RPO、校验失败或存储不足时立即告警。

### 16.3 恢复方式（P0）

- 支持整套系统、单租户、单机器人配置、规则版本和指定时间点恢复。
- 恢复前展示来源、目标、数据范围、预计影响、覆盖对象和校验结果。
- 覆盖式恢复前自动创建当前状态备份，并执行审批及二次确认。
- 优先恢复到隔离环境，验证记录数、文件哈希、权限、规则和关键流程后再切换生产。
- 当前开发切片仅实现“恢复前自动备份 + 当前库受控合并 + 自动化强制暂停”，不应宣称已经创建隔离环境；生产上线前必须补齐独立数据库恢复演练与切换审批。
- 恢复完成后机器人保持暂停；灾前遗留发送任务不得自动重放。
- 人工核对任务检查点、消息有效期、幂等窗口和微信登录状态后逐步恢复。
- 从旧时间点恢复时必须与订单和权益权威流水对账，禁止复活已退款/已撤销权益、重置已兑换激活码或重复赠送配额。
- 恢复后先只读重建并校验权益缓存，再开放激活和付费功能。
- 所有恢复行为写入独立且不可由普通管理员修改的审计记录。

### 16.4 建议灾备目标（评审项）

| 数据类型 | 建议 RPO | 建议 RTO |
| --- | ---: | ---: |
| 核心配置、规则、权限、任务状态 | 15 分钟 | 2 小时 |
| 审计日志 | 15 分钟 | 4 小时 |
| 附件、截图等大文件 | 24 小时 | 8 小时 |

- 每季度执行一次抽样恢复测试。
- 每半年执行一次完整灾难恢复演练并形成可审计报告。
- “备份任务成功”不等同于“数据可恢复”，恢复演练结果才是最终判断依据。

## 17. 非功能要求

### 17.1 可靠性

- 同一事件重复投入 10 次，只允许产生一次外部 UI 动作。
- 状态不确定时优先暂停和人工核对，不以自动重试掩盖不确定性。
- 中控服务重启后可从持久化检查点恢复，不丢失已接收事件。
- 单个执行端故障不得拖垮其他执行端或后台管理服务。

### 17.2 性能与容量

- 后台普通列表和查询在常规负载下 P95 响应时间不超过 2 秒。
- 控制指令到在线 Agent 的 P95 下发时间不超过 5 秒。
- UIA 实际吞吐由微信客户端和频控决定，不以无限并发作为性能目标。
- 容量模型按租户数、账号数、日消息量、附件量、并发客服数和保留期估算。
- 业务 API、规则和权益服务使用无状态实例横向扩容；事件以 `租户 + 微信账号 + 会话` 分区，保证单会话有序。
- 每个微信实例只允许一条有界串行 UI 队列；总体吞吐通过增加授权账号及独立 Windows 会话扩展，禁止并发点击同一窗口。
- 入口按租户、账号和操作类型限流；高水位时延迟或合并备注任务，优先保留 @、人工接管和急停事件。
- 生产高突发设计、容量公式、降级和压测基线见 `docs/HIGH_BURST_ARCHITECTURE.md`。

### 17.3 可维护性

- 服务、Agent、数据库迁移和 UI 适配包均需明确版本和兼容范围。
- 配置变更可审计、可灰度、可回滚。
- 错误码需稳定、可检索并关联处理手册。
- 提供部署、升级、回滚、故障处理、备份和恢复操作手册。

### 17.4 可用性目标

- 平台自身可用性目标与微信客户端、账号风控和网络等外部依赖分开计算。
- UIA 不可用时后台仍可查询历史、处理告警和执行暂停操作。
- 生产环境需明确维护窗口、兼容性验证窗口和微信重新登录责任人。

## 18. 关键状态模型

### 18.1 账号状态

`待配置 -> 待登录 -> 在线 -> 忙碌/人工操作 -> 异常 -> 离线 -> 禁用`

### 18.2 会话状态

`机器人处理 -> 等待规则结果 -> 待人工 -> 人工处理中 -> 已解决 -> 冷却期 -> 恢复机器人`

### 18.3 任务状态

`草稿 -> 待审批 -> 已预约 -> 执行中 -> 已暂停 -> 已完成/部分完成/失败/已取消`

### 18.4 规则状态

`草稿 -> 测试通过 -> 待审批 -> 已发布 -> 已暂停 -> 已回滚/已归档`

### 18.5 服务权益状态

`待激活/已预约 -> 有效 -> 宽限期/已暂停 -> 已过期/已撤销/已退款`

## 19. 核心业务流程

### 19.1 新账号接入

创建租户和权限 -> 注册执行设备 -> 环境自检 -> 授权人员扫码登录 -> 绑定微信账号 -> 收发测试 -> 配置频控和服务时间 -> 灰度上线。

### 19.2 收到消息并自动回复

执行端捕获 -> 标准化和去重 -> 联系人与合规校验 -> 获取会话锁 -> 规则匹配 -> 调用业务服务 -> 生成回复 -> 内容检查 -> 排队发送 -> UI 界面确认 -> 审计落库。

任何步骤超时或结果不确定时，不盲目重发，进入待核对或转人工。

### 19.3 受控批量外发

选择目标 -> 去重及排除名单 -> 编辑模板 -> 变量预览 -> 试发 -> 风险检查 -> 审批 -> 预约 -> 分片限速 -> 逐条发送 -> 分类记录结果 -> 仅重试明确失败项 -> 输出报告。

### 19.4 人工接管

触发转人工 -> 原子锁定会话 -> 停止机器人发送 -> 分配客服 -> 客服处理 -> 记录结果和摘要 -> 进入冷却期 -> 确认无人工输入 -> 恢复机器人。

### 19.5 掉线与恢复

心跳异常 -> 停止领取新动作 -> 冻结未确认动作 -> 告警 -> 定位微信/桌面/网络原因 -> 人工登录或受控恢复 -> 能力自检 -> 核对未确认动作 -> 分批恢复任务。

### 19.6 服务激活与到期

接收订单/激活码/授权命令 -> 校验来源与目标 -> 选择通用套餐和期限 -> 预览开始/结束时间 -> 创建不可变权益流水 -> 权益生效 -> 发送激活消息 -> 到期提醒 -> 安全停用付费功能 -> 保留审计与续费入口。

## 20. 实施分期与商业首版范围建议

### 20.1 UIA 可行性验证门槛

在正式产品开发前，必须先使用计划投入生产的微信版本、Windows 版本、DPI、语言和桌面会话方案完成技术验证：

- 连续稳定运行不少于 72 小时，并完成不少于 500 条受控文本消息收发。
- 消息识别和发送界面确认成功率不低于 98%，错发和重复发送为 0。
- 覆盖网络中断、微信重启、窗口遮挡、未知弹窗、锁屏、Agent 重启和中控重启测试。
- 验证登录、会话列表、目标会话、输入框、发送结果等关键控件能够被 UIA 稳定识别。
- 形成控件树调查、兼容性矩阵、故障记录和风险报告。
- 若关键控件无法稳定识别，或无法做到目标身份二次校验和失败关闭，则停止进入产品开发，不通过注入或协议破解补足。

### 20.2 一期 P0

- 数据模型原生支持多租户，首个交付可先启用单租户。
- 多执行端、多账号、环境自检和版本兼容管理。
- 文本消息采集、规则回复、幂等队列和会话锁。
- 会话中心、基础联系人、人工接管和客服分配。
- 联系人/群自动备注、群内 @ 监听、基础服务包、六种服务期限和权益校验。
- 后台激活、一次性激活码、续费、到期提醒和权益审计。
- 定时任务和受控批量外发。
- RBAC、MFA、审批、审计、脱敏和紧急停止。
- 监控、告警、诊断、自愈和灰度更新。
- 全量/增量备份、时间点恢复、租户恢复和恢复演练。

### 20.3 二期 P1

- 图片、文件、链接等附件处理。
- 高级通用群内玩法、AI 知识库和业务系统集成。
- 完整多租户产品化、SSO、许可证、套餐和计费。
- 高级流程编排、客服 SLA、质检和运营报表。

### 20.4 三期 P2

- 多地域灾备和更细粒度的数据隔离方案。
- 规则智能推荐、会话摘要、客服辅助和质量分析。
- 游戏专属服务、游戏适配包、开放平台、插件机制和行业解决方案包。

## 21. 首版验收基线

| 验收项 | 基线标准 |
| --- | --- |
| 离线发现 | 连续心跳丢失后 60 秒内标记异常，2 分钟内发出告警 |
| 紧急停止 | 在线 Agent 接到指令后 30 秒内停止产生新的 UI 操作 |
| 安全模式 | 未识别微信版本或关键控件缺失时不发送消息并立即告警 |
| 幂等 | 同一事件重复投入 10 次，只产生一次外部 UI 操作 |
| 会话互斥 | 人工接管期间机器人及批量任务不得向该会话发送 |
| 自动备注 | 目标身份不确定或手工备注冲突时不得覆盖；所有修改可追溯并可回滚 |
| @ 消息 | 同一 @ 消息重复采集 10 次只触发一次；机器人自身消息不得形成响应循环 |
| 权益控制 | 未激活、过期、冻结和撤销状态均不能调用受限功能，前后端校验结果一致 |
| 激活安全 | 无有效订单、激活码或授权管理员身份的群消息不能创建有效权益 |
| 并发兑换 | 同一单次激活码并发提交 100 次，只生成一份权益和一次成功流水 |
| 期限计算 | 30/60/90 天、半年、一年和永久的边界日期及时区测试全部通过 |
| 到期通知 | 每个提醒节点最多发送一次，续费后按新结束时间重新计算 |
| 恢复防复活 | 恢复旧备份不会复活已撤销/退款权益、重置激活码或重复增加配额 |
| 配置发布 | 生产配置可追溯发布和审批，并能在 5 分钟内回滚 |
| 权限隔离 | 越权 API 被拒绝并写审计，跨租户自动化测试全部通过 |
| 权限撤销 | 用户或 API Key 撤销后 5 分钟内现有访问失效 |
| 操作追踪 | 每个任务可通过任务 ID 查询完整执行链路 |
| 日志脱敏 | 日志、截图和诊断包不得出现密码、Token 或密钥 |
| 备份完整性 | 每份备份具有清单、校验和及自动校验结果 |
| 恢复能力 | 在隔离环境达到约定 RPO/RTO，并通过数据与功能校验 |
| 恢复防重放 | 恢复后默认暂停，未经核对不得执行灾前遗留外发任务 |
| 审计防篡改 | 应用和普通管理员账号均不能修改或覆盖审计记录 |

## 22. 需要业务方确认的决策

1. 部署形态：客户私有化部署、托管专有环境，还是 SaaS 多租户。
2. 首期规模：微信账号数、Windows 设备数、日均/峰值消息量和客服人数。
3. 首期消息类型：仅文本，还是同时支持图片、文件、链接和语音。
4. 首期业务重点：客服自动回复、内部通知、客户运营，还是业务查询。
5. AI 能力：是否接入大模型、使用哪类知识库、数据是否允许离开客户环境。
6. 数据策略：聊天正文、附件、截图和审计日志各自的保留期限。
7. 灾备指标：是否接受本文建议的 RPO/RTO，异地备份放置在哪个安全域。
8. 审批策略：哪些外发量、数据导出和恢复操作必须双人审批。
9. 兼容范围：指定支持的 Windows、微信版本、DPI、语言和远程桌面方案。
10. 合规责任：账号授权、联系人授权、隐私告知、退订和内容审核的责任边界。
11. 自动备注字段：联系人和群备注需要包含哪些业务字段，是否允许同步修改微信界面备注。
12. 游戏功能已延期；进入后续立项时再确认游戏名称、区服体系、数据来源和指令。
13. 高级玩法：签到、积分、排行、组队、活动等功能的规则、奖励类型和风控限制。
14. 激活渠道：后台、支付订单、激活码和群管理员命令中，首期启用哪些渠道。
15. 续费策略：提前续费是叠加时长还是从付款日重新计算，升级是否按剩余价值折算。
16. 服务对象：首期套餐按联系人、群、微信账号还是租户授权，以及是否允许转移。

## 23. 明确不在首版承诺的事项

- 绕过微信安全机制、风控、验证码、扫码登录或封禁。
- 使用 Hook、注入、协议破解或修改微信客户端。
- 未经授权的营销、批量加好友、批量拉群或骚扰式触达。
- 可靠获取微信客户端未展示或执行端离线期间的完整历史消息。
- 将 UIA 界面确认等同于对方实际送达或已读。
- 跨设备无人工参与地恢复微信登录态。
- 在任意未知微信新版本上继续自动点击。
